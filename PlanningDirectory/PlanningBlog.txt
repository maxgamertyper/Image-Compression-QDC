OK after about an hour of pondering, this is the final *i think* most optimal solution

3 "word" types
bit-ant-pre *short for bit antecendant-prefix* {}
bit-pre *short for bit prefix* ()
bit *just a bit; 1 or 0* []

file:

Metadata *the only byte-driven part* (16 bytes):
File signature (4 bytes)
Image Height (4 bytes *so its compatible with PNG at highest*)
Image Width (4 bytes *so its compatible with PNG at highest*)
Compressor version major (1 byte)
Compressor version minor (1 byte)
Variable Command (1 byte *dynamic so its optimal to size*)
Initial variable size (1 byte)

Payload:

Section 1* (literal color values):
{bit-ant-pre *length determined by Initial bit-prefix size in metadata*} [(000) *always 3 bits in size as 0-255 is 8 bits and 000 has 8 combinations* 0 (000) 1]
oh hey! data ended! find the next square data and insert it. Is there a command to change the bit-ant-pre bit size?
do that a lot

Section 2* (rectangle information):
check for indexing command
read 2 indexing command lengths (length,width)

* each contains 4 channels for R,G,B,A

Tail:
Integrity Hash (32 bytes since its sha-256)


there are 3 reading modes: Master, Variable (has square version too), and Data
reading always starts as master where the 16 bytes of metadata are read
while reading, the variable command is set and the Initial variable size is set
the master reads the next *ant-pre variable* bits for the bit-ant-pre
it then goes into Data mode where Commands dont need to be checked as its raw data
once the data ends, master takes over
data block end means that a rectangle should be inserted *its built sequentially*
master checks for a variable command *if one is found it goes into square variable for its length*
Master goes into data and reads the information
then goes back to where it left off in the literal values
repeat
once its done it reads the tail and verifys the results with the sha-256 hash

im thinking of having a kind of rolling dictionary in the encoder and decoder, i think v1 will just be an entire dict and v2 can have a sliding windo for like 100 pixels

so for v1 heres how itll work:

there will be a default lookup table where the key = value
and there will be a bitset for if that value has been set (will reset every 1000 pixels or smth in sliding window)

if the value has been set, it does not check for a key swap bit (1)
if the value has not been set, it does check for a key swap bit (1)

the bit can be 2 things; 0 or 1 (shocker)

if its a 0, it means dont swap this key with anything, its useless as this only occurs once

Or

1: swap this key with another to provide a shortened key for a larger bit sequence


example:


lets say i have 3 pixels: pixel a (value 200, occurs twice), pixel b (value 10, occurs once), and pixel c (value 0, occurs twice)

*im trying to cover edge cases so this might be weird explanation*

the decoder will read pixel a (200) and then check the bitset for if it has been updated (it hasnt as its the first pixel)
the decoder will then check the next bit since it hasnt been updated.
In this example we will get a 1 (update the key for 200)
the following data will tell it what key to update to

it'll probably be in the chunk kind of setup so like this
(000) *1 bit* 1 *swap the keys 1 and 255*

The encode will decide which key goes where based on inital size and data frequency

then the decode will swap the data in the LUT

then it will read pixel B and do the same thing
10 *has it been assigned? No* 0 *should i update the key? No*
(I could also make 10 a key for something else if it occurs first, i.e keys 0-9 are filled and 255 is the next most frequent so swap it with the key 10)

then it will read pixel C; (since Pixel C occurs the same frequency as pixel A, it should also have a small key)
it will read the 0 see that it has not been assigned
and then check for the next data to see if it should switch

Here: we dont want to label everytime that we dont want to switch the key
so we say Yes, we should change the key (1)
and then set the new key value to 0 (the same as before)

this will update the bitset and say hey, this has been updated, dont look to change it
and so we dont have to store that extra info
